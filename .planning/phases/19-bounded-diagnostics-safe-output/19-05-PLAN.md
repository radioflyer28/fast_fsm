<objective>
Make trace logging payload-free by default and logging configuration application-safe and reversible.

Purpose: Implement D-14 through D-17 so enabling trace cannot leak payloads or invoke representations, custom redaction fails closed, and library configuration never commandeers application logging.
Output: Public minimum trace/redactor/handle contracts, owned-handler generation logic, setter delegation, and performance/structure proof.
</objective>

## Artifacts this phase produces

- New frozen slot dataclass `FSMTraceEvent` with documented fields `operation`, `stage`, `result`, `trigger`, `source_state`, `destination_state`, `positional_args`, `keyword_args`, and `error`; raw fields exist only in the ephemeral object passed to an explicitly supplied redactor and are never placed in records.
- New type alias `FSMTraceRedactor = Callable[[FSMTraceEvent], Mapping[str, object] | None]`; accepted output keys are `operation`, `stage`, `result`, and `detail`, with scalar-only values and an explicit bounded string length.
- New slot-backed `FSMLoggingHandle` fields `_logger`, `_handler`, `_prior_level`, `_prior_propagate`, `_configured_level`, `_configured_propagate`, `_generation`, and `_restored`, with idempotent `restore()`.
- New private `_FSMStreamHandler` ownership/generation marker, `_emit_fsm_trace()`, and `_next_fsm_logging_generation()`.
- `configure_fsm_logging()` returns `FSMLoggingHandle` and adds keyword-only `propagate: bool | None = None` and `redactor: FSMTraceRedactor | None = None`; `set_fsm_logging_level()` accepts/delegates those keyword-only options and returns the handle.
- No new dependency, background logger, global handler clearing, diagnostic traversal, or non-O(1) disabled-trace work is added.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime payload → trace event/redactor/record | Raw caller and exception data is sensitive and representation may have side effects. |
| library configuration → application logger | Logger handlers/filters/formatters and propagation belong to the host application. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-19-21 | Information Disclosure | custom redactor failure | high | mitigate | Minimum ephemeral event, strict output allowlist/bounds, fixed failure category or suppression, no raw fallback. |

| T-19-24 | Tampering | stale restore handle | high | mitigate | Identity plus generation/value comparison and idempotent restore. |
</threat_model>
