<interfaces>
Runtime selection contracts created by Plans 22-01 and 22-02:
- Sync and async selectors return one fully eligible `_PreparedDispatch` or one terminal `TransitionResult` and never finalize observers themselves.
- `_PreparedDispatch.entry` is the exact selected/evaluated `TransitionEntry`; its `priority` is collision-proof internal metadata.
- `_execute_transition` / `_execute_transition_async` consume one prepared winner and `_commit_transition` is the only history/state mutation seam.
- `_LIFECYCLE_STAGE_SELECTION` is used only for normal group exhaustion; missing trigger remains resolution and candidate exceptions retain guard/state-permission stages.

Existing additive record compatibility:
- `TransitionResult` keeps the legacy first five fields and uses `compare=False` for lifecycle additions.
- `TransitionRecord(from_state, trigger, to_state, timestamp)` is slotted; new constructor input must be trailing/defaulted if public direct construction is preserved.
- `FSMTraceEvent` is frozen/slotted and allocated only after the trace-level guard for an explicit redactor.
- `_emit_fsm_trace()` creates fixed scalar metadata and must never expose raw args, kwargs values, condition representations, or exception text.
</interfaces>
