<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| subprocess results -> manifest | Test/coverage/tool output becomes trusted release evidence. |
| tracked manifest -> CI verdict | Repository JSON controls regression and freshness decisions. |
| lock/build pins -> package build | Supply-chain inputs produce wheels and compiled extensions. |
| workflow events -> release jobs | Untrusted pull-request content and trusted tag events share gate definitions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan | Verification | Residual Risk |
|-----------|----------|-----------|----------|-------------|-----------------|--------------|---------------|
| T-15-06 | Tampering | evidence manifest and artifact collection | high | mitigate | Deterministic in-memory regeneration, read-only CI check, field-level diff, coverage non-regression, repeatable wheel inputs with independent records, and a complete recursive slots inventory containing both registered exceptions. | Stale-field/no-rewrite tests, one-pure/multiple-compiled order-independence tests, recursive omission tests, plus `task release-baseline-check`. | A reviewer can intentionally approve a regenerated lower baseline; reviewed diffs make that decision visible. |
| T-15-07 | Spoofing | subprocess/tool output | high | mitigate | Use argument arrays, structured JUnit/coverage JSON, explicit return-code checks, and metadata version APIs. | Failed/partial subprocess fixture tests. | Compromised installed tools can forge their own output; exact lock pins and CI isolation reduce likelihood. |
| T-15-08 | Tampering | dependency/build tool resolution | high | mitigate | Existing package names only, exact build-system pins, tracked uv.lock, pure mode established before/during every clean install, and immediate source-origin preflight after `uv sync --locked` across the supported matrix. | `uv lock --check`, workflow ordering tests, and matrix sync/preflight jobs. | Upstream registry compromise is transferred to the package index/action ecosystem; no new dependency is introduced. |
| T-15-09 | Elevation of Privilege | release workflow | high | mitigate | Gate release jobs behind reusable read-only checks; retain GitHub environment/token permissions only where publication needs them. | Workflow dependency review and tag dry-run validation. | GitHub-hosted runner/action compromise is third-party platform risk. |
| T-15-10 | Repudiation | advisory ty result | low | accept | Keep ty in its own named visible job with advisory conclusion; mypy supplies the blocking audit trail. | Workflow job names and conclusions visible in Actions. | Advisory feedback can be ignored by maintainers, which is intentional under D-05. |
</threat_model>
