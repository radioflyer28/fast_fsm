# External Integrations

**Analysis Date:** 2026-08-29

Fast FSM has no runtime network or service integrations. It is an embeddable, in-memory Python library; callers provide callback and condition code when integrating it with their own applications.

## APIs & External Services

**Runtime service APIs:**
- None detected - `src/fast_fsm/core.py`, `src/fast_fsm/conditions.py`, `src/fast_fsm/validation.py`, and `src/fast_fsm/visualization.py` import only Python standard-library modules plus the runtime `mypy-extensions` dependency.
- Async I/O boundary - `AsyncStateMachine` and `AsyncCondition` in `src/fast_fsm/core.py` and `src/fast_fsm/conditions.py` can await caller-defined I/O, but the package supplies no HTTP client, API SDK, endpoint, retry policy, or service authentication.

**Diagram/export formats:**
- Mermaid and PlantUML - `src/fast_fsm/visualization.py` returns diagram text for a caller or external renderer; it does not call Mermaid, PlantUML, or a hosted rendering API.
- JSON-compatible topology - `to_json()` in `src/fast_fsm/visualization.py` and `to_dict()`/`from_dict()` in `src/fast_fsm/core.py` exchange plain Python dictionaries. `json` is used for serialization/report output in `src/fast_fsm/validation.py`; YAML/TOML parsing is left to the caller and is not a package dependency.

## Data Storage

**Databases:**
- None - FSM state and transitions are held in in-memory dictionaries and objects in `src/fast_fsm/core.py`; no SQLite, SQL client, ORM, or database connection configuration is present.

**File Storage:**
- None at runtime - `fast_fsm` does not persist state or manage files. The example in `src/fast_fsm/core.py` shows callers loading a JSON file before passing its dictionary to `StateMachine.from_dict()`; file I/O belongs to the caller.
- Build artifacts only - wheels, source distributions, Sphinx output, and compiled binaries are generated by `.github/workflows/release.yml`, `.github/workflows/docs.yml`, `setup.py`, and `Taskfile.yml`, not by application runtime code.

**Caching:**
- None - No cache service or cache client is imported. Timing guards such as `TimeoutCondition`, `CooldownCondition`, and `ElapsedCondition` in `src/fast_fsm/condition_templates.py` retain only local in-memory timing state.

## Authentication & Identity

**Auth Provider:**
- None - The package has no user identity, session, OAuth, token exchange, credential store, or authorization middleware. Conditions may inspect caller-supplied keyword arguments, as implemented by `src/fast_fsm/conditions.py` and `src/fast_fsm/condition_templates.py`.

**CI identity:**
- GitHub Actions token permissions - `.github/workflows/docs.yml` grants Pages deployment permissions (`pages: write`, `id-token: write`) to the workflow; `.github/workflows/release.yml` grants release contents write permission. These credentials are workflow-hosted and are not package runtime configuration.

## Monitoring & Observability

**Error Tracking:**
- None - No Sentry, OpenTelemetry, hosted monitoring SDK, or error-reporting endpoint is configured.

**Logs:**
- Python `logging` only - Logging helpers and named FSM logging are implemented in `src/fast_fsm/core.py`; configuration is exposed through `configure_fsm_logging()` and `set_fsm_logging_level()` from `src/fast_fsm/__init__.py`.
- Test log defaults - `pyproject.toml` sets pytest `log_level`, `log_format`, and `log_date_format`; this affects test output only.

## CI/CD & Deployment

**Hosting:**
- GitHub Actions - `.github/workflows/ci.yml` runs Ruff, ty, the pure-Python test matrix, mypyc build smoke tests, and the compiled performance gate.
- GitHub Pages - `.github/workflows/docs.yml` builds Sphinx HTML and deploys `docs/_build/html` using `actions/configure-pages`, `actions/upload-pages-artifact`, and `actions/deploy-pages`.
- GitHub Releases - `.github/workflows/release.yml` builds platform wheels with `pypa/cibuildwheel`, builds a source distribution with `uv build --sdist`, uploads artifacts, and creates a release with `softprops/action-gh-release` on `v*` tags.

**CI Pipeline:**
- `ci.yml` tests CPython 3.10–3.14 on Ubuntu, Windows, and macOS; the same file verifies `core.py` compilation and runs the slow performance benchmark on pushes to `main`.
- `release.yml` targets Linux x86_64/aarch64, Windows AMD64, and macOS x86_64/arm64/universal2; it skips musllinux and selected emulated/cross-compiled test combinations as documented in that workflow.
- PyPI publishing is not active - the `publish_pypi` job in `.github/workflows/release.yml` is commented out and would require repository configuration/secret setup before enabling.

## Environment Configuration

**Required env vars:**
- None for library runtime, tests, docs, or standard builds. Dependency and tool configuration is committed in `pyproject.toml`, `uv.lock`, `Taskfile.yml`, and `docs/conf.py`.
- Optional `FAST_FSM_PURE_PYTHON=1` - Read by `setup.py` to suppress mypyc compilation; CI and pure-Python tasks set it in `.github/workflows/ci.yml`, `.github/workflows/docs.yml`, and `Taskfile.yml`.

**Secrets location:**
- None required by `fast_fsm` runtime. GitHub-managed workflow credentials are used by Actions according to permissions in `.github/workflows/docs.yml` and `.github/workflows/release.yml`.
- A future PyPI publish would use a repository/environment secret or trusted publishing configuration referenced (but currently disabled) in `.github/workflows/release.yml`; no secret value is present in the repository.

## Webhooks & Callbacks

**Incoming:**
- No HTTP/webhook endpoints - The library exposes Python callbacks (`on_enter`, `on_exit`, listener hooks, and condition callables) in `src/fast_fsm/core.py`; these are in-process extension points, not network callbacks.

**Outgoing:**
- No outbound webhooks - Transition listeners and state callbacks in `src/fast_fsm/core.py` execute caller-provided functions. Any notification, API call, or persistence action must be implemented by the embedding application.
