<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> public registration API | Untrusted Python objects cross the exact-bool, endpoint, priority, and ownership boundary. |
| immutable request -> published topology | A complete local plan must be validated before any shared slot or graph version changes. |
| selected entry -> callbacks/results/history | Library mode metadata must remain authoritative without entering caller payload. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-01 | Tampering | `internal` public boundary | high | mitigate | Exact `type(...) is bool` validation before normalization/publication plus pure/native structural tests. |
| T-28-02 | Tampering | canonical request transaction | high | mitigate | Canonical identity validation, prepare-all/publish-once mutation, topology/version fingerprints, and deterministic ownership interruption tests. |
| T-28-03 | Tampering / Information Disclosure | callback/result boundary | medium | mitigate | Store mode only on immutable topology/result/history fields; assert caller kwargs are byte-for-byte-equivalent and bounded errors contain no object repr. |
| T-28-04 | Denial of Service | registration ownership | high | mitigate | Retain existing single-owner envelope, release in `finally`, use barrier-driven contention/interruption tests, and prove subsequent reuse. |
| T-28-05 | Denial of Service | singleton/group dispatch | high | mitigate | Carry one scalar on the selected entry; add no registry scan, sorting, reflection, or dispatch-time collection copy. Structural proof is completed in Plan 03. |
</threat_model>
