<interfaces>
Existing evidence conventions to reuse:
- `tools/artifact_conformance.py` serializes canonical JSON with sorted keys, compact separators, and `allow_nan=False`.
- `tools/release_evidence.py` validates child runtime identity before accepting installed semantic/performance evidence and records exact command, module origin/loader, interpreter, platform, samples, and median.
- `benchmarks/performance_demo.py` uses `time.perf_counter_ns()`, `statistics.median`, bounded warmup/sample counts, and environment-labelled observations.

New comparison protocol:
- Required scenario `flat-alternating-cycle` constructs two states/two events, verifies the exact initial identity, executes a complete alternating cycle, and verifies state identity after each event.
- Required scenario `false-guard-no-transition` performs exactly one false guard evaluation, leaves the current state unchanged, and invokes zero transition callbacks in all three lanes. Official 2.5.0 and 3.2.1 APIs can express this contract; a lane that cannot produce it is a semantic contradiction, not an unsupported cell.
- Optional scenarios are admitted only from `SCENARIO_IDS` and may report `unsupported` with an allowlisted reason; the required alternating flat scenario may never be unsupported.
- Parent process imports only stdlib/common helpers, invokes children via subprocess, and accepts only one bounded JSON object per child.
</interfaces>
