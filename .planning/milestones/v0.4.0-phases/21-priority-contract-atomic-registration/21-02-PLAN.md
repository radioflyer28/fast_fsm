<interfaces>
Contracts created by Plan 21-01 and consumed here:
- `TransitionEntry(to_state, condition=None, priority=0)` is the singleton candidate value.
- `_TransitionGroup.candidates` is the immutable ascending tuple for competing candidates.
- `_TransitionSlot = Union[TransitionEntry, _TransitionGroup]` is the value type of each `_transitions[source][trigger]` slot.
- `_PreparedTransition` carries canonical `sources`, `target`, normalized `condition`, and validated priority.
- `_commit_transition_plan` accepts a tuple of prepared requests and advances graph version once iff any slot changes.

Existing integration seams:
- `add_transitions` accepts legacy three/four-field tuples; this plan adds `(trigger, from_state, to_state, condition, priority)`.
- `add_bidirectional_transition` prepares two legs before one commit; each leg needs its own keyword-only priority.
- `add_emergency_transition` prepares one all-state request; its priority applies unchanged to every source.
- `FSMBuilder.add_transition` stages `(trigger, from_state, to_state, condition)` and `build()` currently registers each row separately.
- `StateMachine.clone` copies outer/inner topology dictionaries and version but currently captures without the owner-aware read boundary used by `_graph_snapshot`.
</interfaces>
