Existing core contracts to extend:
- `TransitionEntry(to_state: State, condition: Optional[Condition] = None)` is slotted and is the direct value in `_transitions[source][trigger]`.
- `_PreparedTransition(trigger, sources, target, condition)` is frozen/slotted and is produced only after endpoint and guard normalization.
- `StateMachine.add_transition(trigger, from_state, to_state, condition=None, *, unless=None) -> None` owns once and delegates to `_add_transition_owned`.
- `_commit_transition_plan(plans: Tuple[_PreparedTransition, ...]) -> None` is the sole transition publication/version boundary.
- `Condition`, `FuncCondition`, and `NegatedCondition` normalization occurs before `_PreparedTransition` is created.

New contracts this plan fixes for downstream phases:
- `TransitionEntry(..., priority=0)` remains the direct singleton representation.
- `_TransitionGroup` is private, frozen, slotted, tuple-backed, and sorted by ascending integer priority.
- `_TransitionSlot` is an explicit `Union[TransitionEntry, _TransitionGroup]`; `_transitions` must not use `Any` to conceal the union.
</interfaces>
