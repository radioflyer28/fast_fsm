<interfaces>
`_TransitionGroup.entries` is a frozen, slotted `Tuple[TransitionEntry, ...]` already stored in ascending priority order. `_TransitionSlot` is `Union[TransitionEntry, _TransitionGroup]`.

`StateMachine._merge_transition_slot(existing: Optional[_TransitionSlot], plan: _PreparedTransition) -> _TransitionSlot` is the sole merge seam. `_commit_transition_plan()` publishes replacements only after every planned slot merges and advances `_graph_version` once only when identity changes.

`StateMachine._select_transition_sync(...)` and `AsyncStateMachine._select_transition_async(...)` already perform two mapping lookups, branch directly for a singleton, and scan only `slot.entries` for a group. They are semantic invariants in this phase, not redesign targets.

Public methods whose complexity wording must be synchronized are `StateMachine.can_trigger()`, `StateMachine.trigger()`, `AsyncStateMachine.can_trigger_async()`, and `AsyncStateMachine.trigger_async()`; signatures and runtime behavior remain unchanged.
