## Cross-Phase Integration

| Flow | Wiring Verified |
|---|---|
| Registration | `add_transition(..., priority=...)` → atomic transition plan → direct singleton or immutable ordered group |
| Selection | candidate slot → sync/async selector → one prepared winner → lifecycle, history, result, and trace |
| Construction | builder/declarative/factory/deserialization → canonical registrar → candidate identity through queries and serialization |
| Diagnostics | immutable topology snapshot → candidate-aware validation, paths, and JSON/Mermaid/PlantUML/Markdown output |
| Artifact proof | runtime shape → structural/benchmark checks → source/pure/compiled conformance oracle → release evidence |
| Drone example | telemetry sample → one controller-owned `telemetry_tick` → ordered guards → committed destination callback → adapter command |

The integration checker also performed a direct priority round trip: registrations
at priorities 20 then 0 selected only priority 0, serialized in `[0, 20]` order,
and preserved the selected priority after deserialization. The runnable drone
simulation completed `Mission → EmergencyLanding → Landed` with commands only
from destination-entry callbacks.
