# SPR: StateMachine core API

**Category**: core-api  
**Created**: 2026-03-06  
**Updated**: 2026-08-30 (canonical graph and guard-context seams)

- `StateMachine` and other hot-path classes use `__slots__`; dynamic attribute assignment on core objects is prohibited. The recursive `uv run python tools/release_evidence.py slots-policy --json` audit discovers every relevant `src/fast_fsm` class and fails on an unregistered or omitted exception.
- Core operations (`trigger`, `can_trigger`, `add_state`, `add_transition`) are O(1) via direct dict lookup; compiled `trigger()` throughput target ≥ 200,000 ops/sec.
- `TransitionEntry(to_state, condition)` is the internal container replacing raw dicts; slots-optimised.
- `trigger()` remains value-returning and keeps the first five positional `TransitionResult(success, from_state, to_state, trigger, error)` fields. Additive `committed`, `stage`, and hidden-from-repr/equality `cause` fields describe the truthful lifecycle outcome; `raise_if_failed()` chains `TransitionError` from `cause` when present.
- Ordinary missing-transition `resolution`, false/raising `guard`, and false/raising `state-permission` outcomes are all pre-commit (`committed=False`): each returns one truthful result, retains a raised exception only as hidden `cause`, and passes exactly once through the unchanged ordered `on_failed(trigger, from_state, error, **kwargs)` observer contract. Observer failures are isolated locally and never recurse, replace the original result/cause, or stop later observers.
- `safe_trigger()` wraps `trigger()` in try/except; never raises under any circumstance.
- `add_transition(trigger, from_state, to_state, condition=None, *, unless=None)` — `unless=` is a negation shorthand, mutually exclusive with `condition=`.
- Ordinary transition endpoints resolve through `_resolve_canonical_state()` before mutation: unknown names, foreign same-name objects, null, and unsupported endpoints fail without creating buckets. `_normalize_transition_request()` materializes/validates all sources, target, guards, and duplicate canonical sources; `_commit_transition_plan()` writes only a complete plan and advances graph version once iff its final topology changes.
- `from_state` accepts a string, `State` object, or list of either; fan-out to multiple sources in one call.
- `add_bidirectional_transition(t1, t2, s1, s2, c1, c2)`, `add_emergency_transition(trigger, to_state)`, and `add_transitions(list_of_tuples)` preflight complete prepared plans and then make one all-or-nothing graph commit/version advance; an invalid later entry/leg leaves no prefix mutation.
- `StateMachine.from_transitions(transitions, initial_state)` classmethod builds a machine from a flat list.
- `is_in(state)` — O(1) identity/name check against `_current_state`.
- `can_trigger(trigger)` — evaluates guard condition synchronously before committing; use for pre-flight checks.
- `can_trigger`, `trigger`, `can_trigger_async`, and `trigger_async` share `_prepare_transition()` for one fresh canonical transition lookup and guarded context preparation per public call. Missing and unconditional transitions do not allocate a guard mapping; guarded calls receive the original positional entries plus a fresh sanitized keyword mapping.
- `GuardResult = bool | Awaitable[bool]` and `GuardCallable = Callable[..., GuardResult]` are public from both `fast_fsm` and `fast_fsm.core`. `Condition`, `FuncCondition`, `CompiledFuncCondition`, `NegatedCondition`, `AsyncCondition`, and every built-in template expose compatible `check(*args, **kwargs)` channels; sync dispatch closes/rejects an awaitable while async dispatch awaits it. `NegatedCondition`, `AndCondition`, `OrCondition`, and `NotCondition` forward both channels unchanged and preserve their ordinary left-to-right short-circuit/inversion rules.
- `_condition_children()` recognizes only exact built-in `NegatedCondition._inner`, `AndCondition.conditions`, `OrCondition.conditions`, and `NotCondition.condition` edges. Shared `_evaluate_condition_sync()` / `_evaluate_condition_async()` preserve wrapper boolean semantics and short-circuiting; async leaves are awaited only in the async evaluator. Active wrapper cycles raise `ValueError`, while acyclic shared condition DAGs remain valid.
- Listener protocol: objects with `on_exit_state`, `on_enter_state`, `after_transition` methods; registered via `add_listener(*listeners)`.
- `AsyncStateMachine` subclasses `StateMachine`; adds `trigger_async` / `can_trigger_async` (auto-detect `AsyncCondition`), `on_enter_async(state_name, fn)` / `on_exit_async(state_name, fn)` for async per-state callbacks. Declares `__slots__ = ("_state_enter_async_callbacks", "_state_exit_async_callbacks")` and overrides `__init__` and `clone()` to carry those two dicts. `FSMBuilder` auto-detects async requirement from states/conditions.
- `FSMBuilder` stages only real `State` objects: the exact same object/name is an idempotent no-op, while a different object with the same name raises before changing staged data. A successful `build()` publishes one cached machine only after a local candidate has finished state, transition, and callback wiring; repeated builds return that identical object. `_machine` is therefore both cache and freeze marker: every fluent mutator, callback registrar, and force-mode method first raises `RuntimeError` after publication, while a failed build leaves all staging mutable and retryable. `StateMachine.quick_build()` follows the same canonical identity rule: it preserves supplied initial/`states=` objects and subclasses, creates base `State` objects only for unresolved string endpoints, and rejects distinct same-name objects. Before allocating a candidate, `_preflight_async_requirements()` traverses states, declarative metadata, staged guards, and queued async callbacks with `StateMachine._contains_async_requirement()`'s exact supported-wrapper classifier. Auto mode selects `AsyncStateMachine`; force modes are authoritative; explicit sync rejects the named async component before publication instead of warning and discarding it.
- `CallbackState` extends `State` with `_on_enter` / `_on_exit` slots; use when state-level callbacks needed without losing slots optimisation.
- `DeclarativeState` enables `@transition`-decorated methods on state classes; auto-discovers via `_discover_handlers()`. Ordinary `trigger()` / `trigger_async()` resolve one handler by canonical source state, trigger, and target metadata, then invoke that exact handler once through `_resolve_declarative_handler()` and the sync/async invocation helpers. Direct `handle_event*()` compatibility calls use the same resolver/invocation boundary without inventing a second dispatch path.
- Declarative handler result normalization preserves None/boolean/`TransitionResult` compatibility, but this Phase 16 seam deliberately does not promise handler-versus-callback ordering, handler failure result shape, commit placement, cancellation, or history-on-failure semantics; Phase 17 owns that lifecycle contract.
- `enable_history(max_entries)` accepts only positive non-boolean integers. Validation occurs before replacing existing storage; each valid enable resets records into an empty `deque(maxlen=max_entries)`, whose append-only FIFO eviction is O(1). Disabled history remains `None` (one branch, no buffer allocation), while `history` always makes a defensive `list` copy and clones start history-disabled. The private no-callback `_commit_transition()` seam changes current state and appends a record together, so a committed transition retains history if a later callback fails.
- mypyc compiles `core.py` only; `conditions.py` and `condition_templates.py` must stay interpreted (users subclass `Condition` from Python). `CompiledFuncCondition` therefore remains an interpreted public wrapper with a compiled core invocation bridge, while `TransitionError` remains the sole `native_class=False` exception. ADR-003 records the selective compilation boundary and the two measured instance-`__dict__` slots-policy exceptions.
- `_sanitize_condition_kwargs` filters private/dunder, non-string, and over-100-character keys before retaining the first 50 safe insertion-ordered entries. It copies the mapping but preserves retained value identity and never logs payload values.
- `force_state(name)` sets `_current_state` directly without guard checks; fires full on_exit / on_enter / after_transition callback chain with synthetic trigger `"__force__"`; raises `KeyError` for unregistered state names.
- `reset()` calls `force_state(initial_state_name)`; fires callbacks even when already in initial state.
- `initial_state_name` read-only property returns the name of the state passed to `__init__`; stored in `_initial_state` slot.
- `snapshot()` returns `{"state": current_state_name, "version": 1}`; JSON-serialisable, safe to pickle.
- Private `_graph_snapshot()` is a fresh tuple-backed `_GraphSnapshot` for internal tools only; it retains canonical State/Condition identities while structurally freezing rows/collections. It has machine name, declared initial State, deterministic sorted states/transitions, and the process-local `_graph_version`; it is not a public serialization compatibility promise.
- State registration is exact-identity canonical: the same object is idempotent, while a different object with an already-registered name raises `ValueError` before mutation; null/non-State registration raises `TypeError`.
- `_graph_version` starts at `0` after constructor baseline registration, changes only after a successful topology change (not a same-object registration, exact transition replacement, or current-state movement), and is copied by `clone()` before its independent lineage diverges.
- `restore(snapshot)` validates version/type then calls `force_state(snapshot["state"])`; raises `ValueError` for bad version or non-string state, `KeyError` for unregistered state.
- `clone()` returns a new instance of the same class with identical topology (shared `State` and `TransitionEntry` objects, independent inner transition dicts), current state at initial, empty listener lists; per-state callbacks are shallow-copied.
- `on_enter(state_name, fn)` registers a per-state callback fired after `State.on_enter` and before `on_enter_state` listeners. Signature: `fn(from_state, trigger, **kwargs)`. Multiple callbacks fire in registration order.
- `on_exit(state_name, fn)` registers a per-state callback fired after `State.on_exit` and before `on_exit_state` listeners. Signature: `fn(to_state, trigger, **kwargs)`. Both are stored in `_state_enter_callbacks` / `_state_exit_callbacks` slots (`Dict[str, List]`).
- The Wave 0 `destination-enter` tracer treats an ordinary trigger's destination state-hook exception as a post-commit failed result (`committed=True`, `stage="destination-enter"`, original hidden `cause`), stops later lifecycle callbacks, and uses one `_finalize_failure()` observer pass. Each failure observer preserves `(trigger, from_state, error, **kwargs)`, runs once in registration order, and an observer failure cannot replace the original result/cause or block later observers.
- `from_dict(config, *, name=None, conditions=None)` classmethod builds a machine from a plain dict; required keys: `"initial"` (str), `"transitions"` (list of `{"trigger", "from", "to"}`); optional keys: `"name"` (str), `"states"` (list of extra state names). `"from"` may be a string or a list. `conditions` is an optional `Dict[str, Condition|Callable]` mapping trigger name → guard; applied at construction, same guard applied to all from-states sharing that trigger name. Internally uses `from_states` + `add_transition`.
- `TransitionResult.raise_if_failed()` returns `self` unchanged on success (enabling one-liner chaining like `.raise_if_failed().to_state`); raises `TransitionError` on failure. `TransitionError(RuntimeError)` carries the originating result as `.result` attribute; message includes trigger, from_state, and error string. It is a measured registry exception: `@mypyc_attr(native_class=False)` preserves normal Python exception behavior, so instances can have `__dict__`.
- `CompiledFuncCondition(func, *, name=None, description="")` — an interpreted callable wrapper re-exported from `core.py`; its public class stays in `conditions.py` so an interpreted Python subclass has identical construction and dispatch in pure and compiled artifacts. Its `check()` delegates invocation to a mypyc-compiled core helper after package import, without making the caller-supplied predicate native or claiming a measured wrapper-throughput benefit. It is a measured instance-`__dict__` exception. Async classification inspects a callable and its effective `__call__` hook without invoking it, so callable instances select/reject the correct builder mode before dispatch.
