# SPR: StateMachine core API

**Category**: core-api  
**Created**: 2026-03-06  
**Updated**: 2026-09-05 (measured slots-policy reconciliation)

- `StateMachine` and other hot-path classes use `__slots__`; dynamic attribute assignment on core objects is prohibited. The recursive `uv run python tools/release_evidence.py slots-policy --json` audit discovers every relevant `src/fast_fsm` class and fails on an unregistered or omitted exception.
- Exactly three measured registered exceptions are CompiledFuncCondition, TransitionError, and DiagnosticBudgetExceeded. `CompiledFuncCondition` stays interpreted in `conditions.py` to retain the public Python subclass boundary while its narrow invocation bridge lives in compiled `core.py`; `TransitionError` is the ADR-003 `@mypyc_attr(native_class=False)` built-in-exception boundary; and ADR-006 accepts interpreted `DiagnosticBudgetExceeded` because bounded failures carry `DiagnosticStatus`. They are the only accepted instance-`__dict__` exceptions; the registry does not authorize a runtime-layout or compilation-boundary change.
- Source/trigger lookup and singleton `trigger` / `can_trigger` dispatch are O(1); finite candidate-group construction during registration and ordered selection are local O(k), with no unrelated-graph scan or dispatch-time sort. Compiled singleton `trigger()` throughput target remains ≥ 200,000 ops/sec.
- `TransitionEntry(to_state, condition, priority=0, condition_ref=None)` is the direct, slots-optimised singleton candidate. Competing priorities occupy a private frozen, slotted, tuple-backed ascending group. The optional opaque scalar `condition_ref` is candidate identity for callable-safe reconstruction, never a caller payload. `TransitionEntry`, `_PreparedTransition`, and `_GraphTransition` carry it as a trailing field; `_TransitionGroup.entries` remains the immutable local ordered sequence.
- `trigger()` remains value-returning and keeps the first five positional `TransitionResult(success, from_state, to_state, trigger, error)` fields. Appended defaults are `committed=False`, `stage=None`, hidden-from-repr `cause=None`, and nullable `priority=None`; every appended lifecycle field is excluded from equality so completed sync/async results still compare equal to legacy five-field expectations. Only a completed trigger reports `committed=True`. `raise_if_failed()` returns the same success object and raises concise stage-aware `TransitionError` explicitly chained from `cause` when present, without formatting that cause.
- Ordinary missing-transition `resolution`, false/raising `guard`, and false/raising `state-permission` outcomes are all pre-commit (`committed=False`): each returns one truthful result, retains a raised exception only as hidden `cause`, and passes exactly once through the unchanged ordered `on_failed(trigger, from_state, error, **kwargs)` observer contract. Failure finalization snapshots that registry at entry, so registrations made by an observer begin with the next failed transition. Observer failures are isolated locally and never recurse, replace the original result/cause, or stop later observers.
- A synchronous ordinary `trigger()` runs one fail-fast lifecycle: **pre-commit** before-transition listeners, source `on_exit`, registered source exit callbacks, and exit-state listeners; a no-user-code **commit** updates current state and appends optional history together; **post-commit** destination `on_enter`, registered destination enter callbacks, enter-state listeners, the selected declarative handler, trigger callbacks, and after-transition listeners. Every callback registry preserves registration order; the first ordinary callback exception suppresses the entire remaining suffix.
- Ordinary synchronous `trigger()` is one per-machine ownership envelope: each `StateMachine` owns a slotted private `threading.Lock` and owner-thread marker, rejects same-thread reentry with the stable redacted `RuntimeError` `FSM ownership violation: reentrant trigger` before preparation, calls `_trigger_owned()` for the unchanged Phase 17 transaction, and releases in `finally` only after result construction or failure finalization completes. Every Phase 17 callback region and failure observer remains inside that envelope. An uncaught nested admission error is classified solely at its enclosing lifecycle stage; a callback that catches it may let the outer transition continue. Independent machines do not share a primitive, and same-machine threads receive mutual exclusion only—no fairness, timeout, queue, or global-lock promise. Direct control, async ownership, remaining writers, safe-trigger admission, and the declarative marker retain their separately owned Phase 18 completion rows.
- Every public topology/history mutation and listener/callback/failure-observer registrar has the same one-entry synchronous ownership envelope: validation, listener method extraction, and registry append occur inside it, and each public entry delegates only to a private already-owned body. Batch and bidirectional topology requests therefore retain their Phase 16 normalize/preflight/commit atomicity, callback-time registrations reject before mutation, and registrations made after an operation remain available to the next tuple-snapshot pass in registration order. `AsyncStateMachine` applies its established bound-loop mixed-writer admission policy to inherited graph/history/registrar writes; its two async registrar methods use that same per-machine sync envelope.
- The proposed slotted sync/async lock, loop/task/root, and `ContextVar` representation passed a local native compile/import probe before this tracer was adopted; the `ownership_native_probe` CI job repeats that probe for Python 3.10–3.14. Hosted matrix success is a final Phase 18 evidence gate, not a Wave 0 claim.
- A synchronous lifecycle failure returns the one redacted staged result and is finalized through the existing ordered `on_failed` pass: pre-commit stages preserve source/history-empty with `committed=False`, while post-commit stages preserve destination/one history record with `committed=True`. `_commit_transition()` constructs any history record before mutating either committed field; an ordinary clock/record fault therefore produces a pre-commit `commit` result with the original cause and one observer pass. Every producer uses the one `_LIFECYCLE_STAGE_*` constants catalog (also exposed internally as ordered `_LIFECYCLE_STAGES`); stable callback stage strings include `before-transition`, `source-exit`, `source-exit-callback`, `exit-state-listener`, `commit`, `destination-enter`, `destination-enter-callback`, `enter-state-listener`, `declarative-handler`, `trigger-callback`, and `after-transition`.
- `safe_trigger()` is its own one-entry public ownership writer: it admits with the redacted `safe_trigger` operation label, calls `_trigger_owned()` directly, and releases in `finally`. Ownership, loop, causal-root, foreign-thread, and busy-admission `RuntimeError` values occur before its ordinary `Exception` compatibility barrier and therefore propagate; ordinary post-admission exceptions still return the legacy first-five-field `TransitionResult` shape with a stable redacted error.
- Declarative guard preparation uses one private context-local marker containing exact machine, source, trigger, and target identities. The machine dispatch sets that marker only around the matching state-policy invocation and resets its returned token in `finally`; nested machine scopes therefore restore their outer value, while independent sync threads and async tasks cannot share or consume a mutable global marker. The base declarative class suppresses only its matching duplicate guard evaluation, preserving direct-call compatibility and Phase 17 exactly-once handler order.
- `add_transition(trigger, from_state, to_state, condition=None, *, unless=None, priority=0)` is the only candidate-registration API. `priority` must be an exact built-in non-boolean integer; lower values are earlier, equal-priority nonduplicates fail atomically, and an exact post-normalization duplicate is version-neutral. `unless=` is a negation shorthand, mutually exclusive with `condition=`.
- `_select_transition_sync(..., *, for_query)` and `_select_transition_async(..., *, for_query)` read exactly one source/trigger slot and return either one fully eligible slotted `_PreparedDispatch` or one terminal `TransitionResult`. A singleton stays direct; a frozen group is scanned only in its stored ascending priority order. Each candidate evaluates transition guard, declarative guard, then target permission. Ordinary rejection falls through only within that group; an exception or async cancellation stops selection, and no selector runs callbacks, history, observers, or trace work.
- Cold topology consumers use `_transition_entries(slot)` to obtain an immutable singleton-or-group candidate sequence. Serialization, private graph snapshots, target queries, and reachability flatten that sequence; sync/async selectors retain their direct singleton cast and stored-group iteration, with no projection call, sort, copy, unrelated-topology scan, or async fan-out.
- A successful or evaluated candidate carries its one `entry.priority` scalar into `TransitionResult`, the trailing/defaulted `TransitionRecord.priority` created at the sole `_commit_transition()` seam, and the one outer attempt trace event. Post-selection lifecycle failures retain that selected priority; missing-trigger resolution and normal group exhaustion retain `None`. Priority is never inserted into caller args, callback kwargs, or a second guard evaluation.
- Trace remains metadata-only: `_emit_fsm_trace()` checks the trace level before event allocation or payload/key inspection, emits one `trace_priority` scalar per overall sync/async attempt, and provides the same nullable scalar to an explicit frozen/slotted `FSMTraceEvent` redactor. Redactor output may return bounded scalar `priority`; failed redaction resets it to `None` and never falls back to payload, condition, or error representations.
- Ordinary transition endpoints resolve through `_resolve_canonical_state()` before mutation: unknown names, foreign same-name objects, null, and unsupported endpoints fail without creating buckets. `_normalize_transition_request()` materializes/validates all sources, target, guards, and duplicate canonical sources; `_commit_transition_plan()` writes only a complete plan and advances graph version once iff its final topology changes.
- `from_state` accepts a string, `State` object, or list of either; fan-out to multiple sources in one call.
- `add_bidirectional_transition(t1, t2, s1, s2, c1, c2)`, `add_emergency_transition(trigger, to_state)`, and `add_transitions(list_of_tuples)` preflight complete prepared plans and then make one all-or-nothing graph commit/version advance; an invalid later entry/leg leaves no prefix mutation.
- `StateMachine.from_transitions(transitions, initial_state)` classmethod builds a machine from a flat list.
- `is_in(state)` — O(1) identity/name check against `_current_state`.
- `can_trigger(trigger)` — evaluates guard condition synchronously before committing; use for pre-flight checks.
- `can_trigger`, `trigger`, `can_trigger_async`, and `trigger_async` share `_prepare_transition()` for one fresh canonical transition lookup and guarded context preparation per public call. Missing and unconditional transitions do not allocate a guard mapping; guarded calls receive the original positional entries plus a fresh sanitized keyword mapping.
- `GuardResult = bool | Awaitable[bool]` and `GuardCallable = Callable[..., GuardResult]` are public from both `fast_fsm` and `fast_fsm.core`. `Condition`, `FuncCondition`, `CompiledFuncCondition`, `NegatedCondition`, `AsyncCondition`, and every built-in template expose compatible `check(*args, **kwargs)` channels; sync dispatch closes/rejects an awaitable while async dispatch awaits it. `NegatedCondition`, `AndCondition`, `OrCondition`, and `NotCondition` forward both channels unchanged and preserve their ordinary left-to-right short-circuit/inversion rules.
- `_condition_children()` recognizes only exact built-in `NegatedCondition._inner`, `AndCondition.conditions`, `OrCondition.conditions`, and `NotCondition.condition` edges. Shared `_evaluate_condition_sync()` / `_evaluate_condition_async()` preserve wrapper boolean semantics and short-circuiting; async leaves are awaited only in the async evaluator. Active wrapper cycles raise `ValueError`, while acyclic shared condition DAGs remain valid.
- Listener protocol: objects with `on_exit_state`, `on_enter_state`, `after_transition` methods; registered via `add_listener(*listeners)`.
- `AsyncStateMachine` subclasses `StateMachine`; `trigger_async()` has an explicit same-slot lifecycle runner rather than a sync-runner-plus-tail. It runs synchronous callbacks inline, awaits registered source exit callbacks immediately after synchronous source callbacks, and awaits registered destination enter callbacks immediately after synchronous destination callbacks; then it continues through listeners, the exactly-once declarative handler, trigger callbacks, and after listeners. Ordinary failures return the same redacted stage/commit/history/cause result as sync dispatch. `on_enter_async(state_name, fn)` / `on_exit_async(state_name, fn)` register those async per-state callbacks. Its exact subclass `__slots__` are `("_state_enter_async_callbacks", "_state_exit_async_callbacks", "_async_ownership_lock", "_async_admission_lock", "_bound_loop", "_bound_loop_thread_id", "_async_owner_task", "_async_owner_root", "_sync_admission_reservations")`: async callback registries plus per-instance ownership, admission, and loop-binding state. `__init__` initializes that state; `clone()` copies registries into independent containers and starts with fresh ownership primitives and cleared loop binding. `FSMBuilder` auto-detects async requirement from states/conditions.
- An `AsyncStateMachine` now permanently binds to the exact running event loop (and thread) used by its first `can_trigger_async()` or `trigger_async()` operation. A foreign or later loop is rejected before transition preparation. `trigger_async()` acquires a per-machine `asyncio.Lock` only after that check; independent same-loop tasks therefore serialize without blocking the event loop. Its owner marker is installed only after lock acquisition and cleared in `finally`, so cancellation while waiting leaves no owner and cancellation while owning releases the machine after the existing Phase 17 cancellation finalizer completes. Pre-bind synchronous writers share a short metadata admission gate with loop binding; after binding, foreign threads and active async ownership are rejected rather than blocking the loop.
- The async owner establishes a private `ContextVar` root with explicit `set()` / `reset(token)` handling. Direct awaited reentry and child tasks created from an owned callback inherit that root and raise a redacted `RuntimeError` before awaiting the machine lock, avoiding parent-child deadlock. Nested work on a different machine may reuse the inherited root. Synchronous callbacks remain inline on the bound loop thread, while registered async callbacks remain awaited at their existing lifecycle slots; Fast FSM never offloads either callback kind.
- `trigger_async()` catches `asyncio.CancelledError` only at its public lifecycle boundary: it creates one redacted observer-facing staged failure, runs ordered failure observers exactly once while isolating observer exceptions, and then bare-re-raises the identical cancellation. Guard and source-side cancellation preserve source state and empty history; destination-side and declarative cancellation preserve the committed destination and exactly one history record. It suppresses the remaining lifecycle suffix and uses neither `asyncio.shield()` nor rollback/compensation.
- `FSMBuilder` stages only real `State` objects: the exact same object/name is an idempotent no-op, while a different object with the same name raises before changing staged data. A successful `build()` publishes one cached machine only after a local candidate has finished state, transition, and callback wiring; repeated builds return that identical object. `_machine` is therefore both cache and freeze marker: every fluent mutator, callback registrar, and force-mode method first raises `RuntimeError` after publication, while a failed build leaves all staging mutable and retryable. `StateMachine.quick_build()` and `quick_fsm()` accept the same 3/4/5-field rows as `add_transitions()`: `(trigger, source, target)`, optional condition, optional exact priority. They collect supplied `State` identities (including list-source expansion), create unresolved names locally, then submit one unmodified complete batch to the canonical registrar. Thus malformed/tied/async-incompatible late rows return no machine and publish no prefix; factories do not sort, merge, tie-break, or assign graph versions themselves. `from_states()` and `simple_fsm()` remain transition-free helpers. Before allocating a builder candidate, `_preflight_async_requirements()` traverses states, plural declarative metadata, staged guards, and queued async callbacks with `StateMachine._contains_async_requirement()`'s exact supported-wrapper classifier. Auto mode selects `AsyncStateMachine`; force modes are authoritative; explicit sync rejects the named async component before publication instead of warning and discarding it.
- `CallbackState` extends `State` with `_on_enter` / `_on_exit` slots; use when state-level callbacks needed without losing slots optimisation.
- `DeclarativeState` retains frozen/slotted plural declaration and bound-handler rows. Runtime resolution is exact source + trigger + target + priority identity after candidate selection; discovery order has no selection meaning. A lone legacy declaration may serve an otherwise unambiguous direct helper call, but plural matches fail closed instead of guessing. Ordinary synchronous `trigger()` invokes the selected handler exactly once after enter-state listeners and before trigger callbacks. `None`, `True`, and successful `TransitionResult` allow the lifecycle to continue; `False`, failed `TransitionResult`, invalid results, and raised exceptions return a post-commit `declarative-handler` failure. Direct `handle_event*()` calls retain their existing compatibility normalization through the same resolver/invocation boundary.
- `enable_history(max_entries)` accepts only positive non-boolean integers. Validation occurs before replacing existing storage; each valid enable resets records into an empty `deque(maxlen=max_entries)`, whose append-only FIFO eviction is O(1). Disabled history remains `None` (one branch, no buffer allocation), while `history` always makes a defensive `list` copy and clones start history-disabled. The private no-callback `_commit_transition()` builds an optional record before appending it and only then changes current state, so an ordinary record-construction fault leaves source/history unchanged while a committed transition retains history if a later callback fails.
- mypyc compiles `core.py` only; `conditions.py` and `condition_templates.py` must stay interpreted (users subclass `Condition` from Python). `CompiledFuncCondition` therefore remains an interpreted public wrapper with a compiled core invocation bridge, `TransitionError` remains the core-only `native_class=False` exception, and interpreted `DiagnosticBudgetExceeded` remains the ADR-006 bounded-diagnostics exception. ADR-003/ADR-006 record the selective compilation boundary and the three measured instance-`__dict__` slots-policy exceptions.
- `_sanitize_condition_kwargs` filters private/dunder, non-string, and over-100-character keys before retaining the first 50 safe insertion-ordered entries. It copies the mapping but preserves retained value identity and never logs payload values.
- `force_state(name)`, `reset()`, and `restore(snapshot)` each acquire the per-machine synchronous ownership envelope exactly once under their own redacted labels, validate inside it, and call the private already-owned `_force_state_owned()` body rather than another public control method. Nested direct control fails before nested validation, callback, state, or history work; `reset()` still fires callbacks when already at initial state.
- `initial_state_name` read-only property returns the name of the state passed to `__init__`; stored in `_initial_state` slot.
- `snapshot()` returns `{"state": current_state_name, "version": 1}`; JSON-serialisable, safe to pickle.
- Private `_graph_snapshot()` is a fresh tuple-backed `_GraphSnapshot` for internal tools only; it retains canonical State/Condition identities while structurally freezing rows/collections. It has machine name, declared initial State, deterministic sorted states/transitions, and the process-local `_graph_version`; it is not a public serialization compatibility promise. Snapshot capture serializes with topology writers, but callback-local capture uses the already-owned boundary so it cannot self-deadlock.
- `_GraphSnapshot.initial_state_name`, `.current_state_name`, and `.state_names` add scalar labels without removing identity fields. Each candidate-complete `_GraphTransition` captures `.from_state_name`, `.to_state_name`, `.condition_name`, exact `.priority`, and optional `.condition_ref`; all are copied inside the snapshot boundary, so later caller mutation of a State or Condition cannot alter a captured diagnostic label.
- Private interpreted `fast_fsm._diagnostics` converts one core snapshot into tuple-backed scalar graph rows. It provides finite `DiagnosticLimits`, scalar `DiagnosticStatus`, and fixed-message `DiagnosticBudgetExceeded(status)` for bounded design-time analysis. `FSMValidator(..., limits=...)` captures exactly once, starts default reachability at declared initial state, reports captured current state separately, reserves result/work before traversal, and never rereads live topology. Exhausted legacy set results raise exactly `diagnostic budget exhausted` rather than returning a partial set.
- The package root explicitly exports only `DiagnosticLimits`, `DiagnosticStatus`, and `DiagnosticBudgetExceeded` from the diagnostics contract. Internal graph rows and the mutable budget remain private implementation seams.
- `_diagnostics.py` stays outside the mypyc `core.py` boundary and must not be imported by core. Diagnostics must not add traversal/allocation to `trigger()`, `can_trigger()`, `add_state()`, or `add_transition()` hot paths; no runtime dependency is added.
- State registration is exact-identity canonical: the same object is idempotent, while a different object with an already-registered name raises `ValueError` before mutation; null/non-State registration raises `TypeError`.
- `_graph_version` starts at `0` after constructor baseline registration, changes only after a successful topology change (not a same-object registration, exact transition replacement, or current-state movement), and is copied by `clone()` before its independent lineage diverges.
- `restore(snapshot)` validates version/type then calls `_force_state_owned(snapshot["state"])`; it raises `ValueError` for bad version or non-string state and `KeyError` for an unregistered state without leaking ownership.
- `clone()` returns a new instance of the same class with identical candidate-complete topology (shared immutable `State`, `TransitionEntry`, and frozen group objects, independent inner transition dicts), starts at the initial state with history disabled, and shallow-copies callback/listener registries into independent list/dict containers. Existing callback/listener objects remain shared by identity, but adding or removing registrations on either machine does not mutate the other. Builders and all public factories construct fresh machines with independent sync/async ownership primitives and cleared owner, causal-root, and loop-binding metadata.
- `on_enter(state_name, fn)` registers a per-state callback fired after `State.on_enter` and before `on_enter_state` listeners. Signature: `fn(from_state, trigger, **kwargs)`. Multiple callbacks fire in registration order.
- `on_exit(state_name, fn)` registers a per-state callback fired after `State.on_exit` and before `on_exit_state` listeners. Signature: `fn(to_state, trigger, **kwargs)`. Both are stored in `_state_enter_callbacks` / `_state_exit_callbacks` slots (`Dict[str, List]`).
- `force_state`, `reset`, and `restore` preserve their direct synthetic-control callback contract inside ownership: they run the legacy best-effort callback chain with trigger `"__force__"`, continue after ordinary callback exceptions, and are not routed through the ordinary-trigger lifecycle result finalizer. A `BaseException` still propagates, but the public `finally` clears the owner and releases the primitive. Clones construct their own lock and owner marker while retaining their existing independent callback registries.
- `to_dict()` emits one deterministic JSON-native row per candidate with `trigger`, `from`, `to`, exact `priority`, and optional opaque non-empty `condition_ref`. `from_dict(config, *, name=None, conditions=None)` validates every row and reference, resolves live guards only from the caller-owned registry, normalizes all rows, and commits once. Explicit `condition_ref` wins; legacy bare trigger keys are accepted only for one expanded candidate and otherwise fail closed as ambiguous. It never serializes callables, exception representations, or private object identities.
- `TransitionResult.raise_if_failed()` returns `self` unchanged on success (enabling one-liner chaining like `.raise_if_failed().to_state`); raises `TransitionError` on failure. `TransitionError(RuntimeError)` carries the originating result as `.result` attribute; message includes trigger, from_state, and error string. It is a measured registry exception: `@mypyc_attr(native_class=False)` preserves normal Python exception behavior, so instances can have `__dict__`.
- `CompiledFuncCondition(func, *, name=None, description="")` — an interpreted callable wrapper re-exported from `core.py`; its public class stays in `conditions.py` so an interpreted Python subclass has identical construction and dispatch in pure and compiled artifacts. Its `check()` delegates invocation to a mypyc-compiled core helper after package import, without making the caller-supplied predicate native or claiming a measured wrapper-throughput benefit. It is a measured instance-`__dict__` exception. Async classification inspects a callable and its effective `__call__` hook without invoking it, so callable instances select/reject the correct builder mode before dispatch.
- Trace logging uses level `logging.DEBUG - 5` and is metadata-only by default. A `trigger()` or `trigger_async()` trace record has only fixed operation/stage/result categories, `trace_arg_count`, and capped sanitized `trace_keyword_names`; it never stores trigger/state names, positional/keyword values, error payloads, or object representations in the message, args, `extra`, or formatted output. The trace helper guards with `logger.isEnabledFor(logging.DEBUG - 5)` before event allocation, map/key traversal, handler lookup, or redactor work, keeping disabled tracing O(1) and compatible with the mypyc trigger floor.
- `FSMTraceEvent` is a frozen slotted ephemeral redactor input with exactly `operation`, `stage`, `result`, `trigger`, `source_state`, `destination_state`, `positional_args`, `keyword_args`, and `error`. It is constructed only when an explicit `FSMTraceRedactor = Callable[[FSMTraceEvent], Mapping[str, object] | None]` is configured. Redactor output may contain only scalar `operation`, `stage`, `result`, and `detail` values, with strings bounded to 200 characters. An ordinary `Exception` redactor failure, non-mapping, forbidden, non-scalar, or oversized output emits only the fixed `redaction_failure` category and never falls back to raw values. Non-`Exception` `BaseException` subclasses (including `KeyboardInterrupt`, `SystemExit`, and `asyncio.CancelledError`) are not converted: they emit no trace record and are re-raised.
- `configure_fsm_logging(level, logger_name, format_string, *, propagate=None, redactor=None)` returns a slotted `FSMLoggingHandle`. It retains every application handler/filter/formatter/order/open state, removes and closes only a stream handler carrying the private frozen `_FSMStreamHandler(generation, redactor, configured_level)` marker, and then creates at most one new marked library handler. `configured_level` distinguishes a reachable library TRACE configuration from DEBUG/INFO handlers when deciding whether legacy payload-bearing records must be suppressed. `propagate=None` preserves application propagation; an explicit boolean is a deliberate library change. The handle stores exactly `_logger`, `_handler`, `_prior_level`, `_prior_propagate`, `_configured_level`, `_configured_propagate`, `_generation`, and `_restored`.
- `FSMLoggingHandle.restore()` is idempotent and removes only its exact marked handler. It restores the previous level only while its generation is current and the logger still contains the configured level; it restores propagation under the equivalent current-generation/value comparison only when configuration changed propagation. Reconfigured or out-of-order handles cannot remove a current handler or overwrite later application values. `set_fsm_logging_level(verbosity, logger_name, *, propagate=None, redactor=None)` validates/maps its established verbosity names and delegates directly to this same configuration seam, returning its handle.
